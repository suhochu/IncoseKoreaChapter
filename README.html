"시스템 엔지니어링 커뮤니티의 운영 자체를 시스템 엔지니어링하다"

"현장의 문제를 직접 해결하는 AI-Native 시스템 엔지니어링 실전 랩(Lab), INCOSE Korea 'Do-Tank' 챕터"

이곳은 INCOSE Korea Chapter의 공식 지식 저장소(Single Source of Truth)입니다. 본 저장소는 별도의 파편화된 문서 폴더를 두지 않고, 챕터의 조직 구성·회원 정보·운영 프로세스·회의 및 의사결정 기록·거버넌스, 도메인별 기술 산출물 및 단계별 AI 아키텍팅 스킬(AI Skills)까지 모든 것을 SysML v2 기반의 System-as-Code(ASELCM_LV1 ~ LV3)로 직접 모델링하고 관리합니다.

우리 챕터는 단순한 이론적 스터디(Think-Tank)를 넘어, 현업 실무자들이 즉각 적용할 수 있는 도메인별(자동차 SDV, 우주 미션 시스템 등) MBSE 레퍼런스 모델과 이를 뒷받침하는 단계별 AI Skills 라이브러리를 애자일(Agile) 방식으로 직접 구축하고 검증하는 'Do-Tank'를 지향합니다.

🎯 1. Vision & Objectives

1.1. Problem Statement (우리가 해결하고자 하는 문제)

  • 국내 SE 전문 인력 감소와 실무적 효능감 부재: 글로벌 시스템 엔지니어링(SE) 확산 추세와 달리 국내 SE 인구가 감소하는 근본 원인은, 교육을 이수하더라도 현업에서 직접적인 효과를 체감하지 못하고 참고할 만한 '구체적이고 실용적인 레퍼런스'가 부재하기 때문입니다.
  • 보여주기식 요식 행위와 기술적 부채의 누적: ISO 26262, ASPICE, ISO/SAE 21434 등 국제 표준 준수를 위해 SE 프로세스가 강제되고 있으나, 요구사항과 아키텍처 문서가 실제 제품(SW/HW/기구)의 품질 향상으로 이어지지 못하고 매 프로젝트마다 지식이 초기화(Reset)되는 악순환이 반복되고 있습니다.
  • 높은 모델링 진입장벽과 표준화된 AI 활용 체계 부재: SysML v2 및 엄밀한 아키텍처 방법론의 높은 러닝 커브와 수작업 공수로 인해 실무자들이 제한된 시간 내에 추적성을 유지하기 어렵고, LLM(AI)을 활용하려 해도 아키텍처 단계별로 검증된 표준 AI Skills(프롬프트·룰셋·워크플로우)가 없어 일관된 아키텍처 품질을 확보하기 어렵습니다.

1.2. System Idea & Objectives (우리의 4대 핵심 목표)

  1. 실천 중심의 'Do-Tank' 조직 재활성화: 이론 스터디를 넘어 실제 동작하고 검증 가능한 산출물을 도출하여 SE의 현장 적용성을 극대화합니다.
  2. 도메인별 End-to-End 실전 레퍼런스 모델 구축: 자동차 도메인의 SDV(Software Defined Vehicle) 전체 비히클과 우주 도메인의 전체 미션 시스템을 대상으로, 운영자 요구사항부터 Simulink 연동 및 오토코드 제너레이션까지 이어지는 디지털 스레드(Digital Thread) 모범 사례를 구축합니다.
  3. AI-Supported Architecting을 위한 단계별 'AI Skills' 개발 및 자산화: 아키텍처 방법론의 각 단계별로 효과적인 시스템 아키텍처 설계, 정합성/추적성 검증, 안전/보안 분석 및 데이터 익명화를 수행하는 재사용 가능한 AI Skills 라이브러리를 개발하고 형상 관리합니다.
  4. 실무자 주도 상향식(Bottom-up) 확산: 경영진 맞춤형 뷰(View)를 통해 리더십을 시각적으로 설득하고, 성공 사례를 경험한 실무진이 현업으로 지식을 전파하여 대한민국이 SE 분야의 Fast Mover로 도약하는 엔진 역할을 수행합니다.

🏗️ 2. Agile System Architecture & AI Skills

본 챕터는 "커뮤니티 운영 시스템"과 "도메인별 기술 레퍼런스 모델"을 동시에 구축하기 위해, ① INCOSE ASELCM (3-System 패턴), ② MagicGrid (2nd Ed. 매트릭스), ③ Agile Vertical-Slice & AI-Supported GitOps를 결합한 하이브리드 애자일 아키텍처 방법론을 표준으로 채택합니다.

2.1. 거시적 생태계 구조: INCOSE ASELCM 3-System Pattern

  • System 1
    산출물 시스템: 워킹그룹이 개발하는 자동차(Automotive_SDV_Reference_Model) 및 우주(Space_Mission_Reference_Model) End-to-End 레퍼런스 아키텍처 모델입니다.
  • System 2
    챕터 운영 시스템: System 1을 기획·개발·검증하고 지식을 교류하는 조직 및 운영 프로세스 자체입니다. 회원 명부, 요구사항, 회의록이 SysML v2 코드로 모델링됩니다.
  • System 3
    환경, 거버넌스 및 AI 통제: 모델링 컨벤션, Git 정책, 통제 규칙과 단계별 02. AI_Architecting_Skills 카탈로그입니다.

💻 6. System-as-Code & AI-Supported Workflow

6.1. 협업 커뮤니케이션

  • Single Source of Truth: GitHub 및 Google Workspace
  • 실시간 소통: 카카오톡 단체방 및 Slack/Discord
  • Vibe Coding with AI: VSCode + SysML v2 환경에 LLM을 연동하여 스캐폴딩 및 추적성 검증 자동화

6.2. Git 형상 관리 & 컨벤션

  • Naming: 정의 요소(PascalCase), 사용 요소(camelCase)
  • AI Skill 표준화: 타겟 셀, 입출력 포맷, 검증 룰셋 필수 포함
  • PR 정책: 개별 브랜치 작업 후 PR 제출, 리뷰 후 메인 병합

🔒 7. Security & Risk Rules (3대 보안 철칙)

현업 실무자들이 소속 기업의 IP나 산업 보안 규정을 침해하지 않도록 아래 철칙을 엄격히 준수합니다.

  1. 데이터 마스킹 및 가상값 치환: 실제 수치/스펙은 가상값(A, B, C)이나 일반화된 데이터로 무조건 치환.
  2. 익명성 보장: 내부 프로젝트 실명이나 대외비 프로그램명은 모델 코드 및 AI 프롬프트에 절대 언급 불가.
  3. 내부 공유 한정 및 반출 통제: 산출물은 승인자에게만 공유되며, 외부 공개 시 사전 승인 및 보안 마스킹 필수.

📖 8. Core Glossary

Do-Tank

이론 스터디를 넘어, 실제 동작하고 검증 가능한 레퍼런스와 AI Skills를 생산하는 실행 중심 조직.

SoI (System of Interest)

모델링 분석 핵심 대상 (예: SDV 차량, 혹은 INCOSE Chapter 조직 자체).

System-as-Code

아키텍처 모델을 텍스트 코드로 작성하여 Git 관리 및 CI/CD를 적용하는 패러다임.

Digital Thread

요구사항부터 V&V까지 모든 요소가 엄격한 메타모델 문법으로 연결되어 추적 가능한 상태.
